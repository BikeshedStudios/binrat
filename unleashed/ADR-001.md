# ADR 001 — isolated local replay substrate

Date: 2026-10-30 · Status: experiment only, authorized by issue #214. No production adoption or migration.

The reviewed substrate is Node + `better-sqlite3` + React V3, with strict source-bound Case contracts. That substrate remains intact in the inherited application. Issue #214 explicitly permits a separate frontend/backend experiment and asks for reliable zero-spend local execution, durable replay and a complete phone journey.

The successor uses a buildless browser surface, Node HTTP and Node's built-in SQLite. This removes runtime dependency installation and native-addon compilation from the owner playtest. It reuses the existing Pons adapter, canonical snapshot digest, checkpoint/status validators and freshness rules directly. There is no replacement evidence schema masquerading as stronger chain provenance.

The inspected owner Tripwire engine couples verified chain/event facts, Cloudflare D1 and Telegram delivery. The pinned public snapshot does not contain all those facts and this mission forbids activation. Importing that engine would imply unsupported authority or require unrelated adapters. The new local replay therefore adopts its bounded generation/cancel model and five-watch/twenty-candidate limits, while declaring its weaker `PINNED_PUBLIC_SNAPSHOT` authority and `LOCAL_RECEIPT_ONLY` outcome. No live Tripwire capability is claimed.

Tradeoffs: Node >=22.13, with Node 24 recommended; one local process and per-browser local sessions; no cloud identity, live data, notification delivery, wallet binding, purchased capacity or cross-specialist work. This is a product experiment, not satisfaction of the founder's live workforce gates. Moxie is its presentation character, not a newly promoted production specialist.

Evidence: source hash validation, inherited 586-test baseline, retained V2 checks, replay/cancel/restart/API tests, seven browser journeys and a bounded hostile review. Owner visual/product acceptance remains pending. Future production adoption needs a separately scoped integration and its own runtime evidence.

Rollback: stop this separate server and leave the branch unused. Existing applications, data and worktrees require no changes.
